1. Set up the skill

Get the MIT-0 Krillion Session Helper source and read SKILL.md before using it. Import the file using your assistant host’s documented skill workflow, or load it as session instructions if that host supports text skills. Installation paths and skill formats vary by host; this document does not promise automatic installation in every assistant.

The host supplies the language model and a browser or public-page retrieval tool. The skill supplies routing and reporting instructions. It is not a game server, MCP server, scoring model, or browser extension. No API key or executable download is needed by the skill.

Start from the Krillion game lobby and read the current mode instructions. Guest play is available. Use the normal sign-in flow for optional account features; never give the assistant passwords, cookie exports or unrelated private files.

2. Choose a route from the player’s situation

SituationRoute and next step
Learn without a timerFree Play: experiment with alternatives and compare the recorded result.
A compact daily roundDaily Challenge: seven prompts, 25 seconds per prompt, one answer each. Follow the displayed game date.
A longer untimed sessionUnlimited: three seven-question legs.
Everyone is online togetherLive rooms: two to eight players share prompts; answers stay hidden until the reveal.
Friends will play laterFriend challenge: share the actual invitation from a completed run so players receive its question set.
A particular subjectThemed Expeditions: select the subject shown in the current lobby.

Return the mode, one reason it fits, and the next action. A lobby visit is not a created room. A visual world changes the setting, not the prompt category.

3. Keep scores tied to the exact prompt

  1. Use the prompt-specific answer checker when the player asks for a check.
  2. Match the question text and its displayed date or identifier before checking an answer.
  3. Report only the displayed acceptance, score and tier. Keep spelling suggestions separate from exact matches.
  4. If the saved pool has no matching record, say that the score was not established. Absence from that pool is not proof that another game will reject the answer.

An accepted answer can score below 100. Do not invent a rarity tier, transfer a score between different prompts, or present a planning suggestion as a completed game action.

4. Try three small examples

“Five of us can play now.”
Recommend a live room, check the current player limit, and offer the visible setup action. Do not invent a room code.
“Can my friend beat this run tomorrow?”
Use the completed run’s asynchronous challenge action. Return the real link for the player to share; do not message contacts without permission.
“Does accepted mean perfect?”
Explain the distinction, then check the selected prompt’s actual recorded score if requested.

During setup, do not expose answer pools unless the players ask for solutions. Start rooms, submit answers, or send invitations only when the user requests those actions.
